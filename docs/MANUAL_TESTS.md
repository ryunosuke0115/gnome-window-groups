# 実機テスト

Ubuntu 24.04 / GNOME Shell 46 の Wayland セッションで実行する確認手順である．以下は期待する結果であり，実施済みの記録ではない．

## 準備

1. README に従ってインストールし，再ログインして有効化する．
2. 同じワークスペースに通常ウィンドウを4つ用意する．同じアプリの別ウィンドウも含める．
3. GNOME・アプリのバージョン，Wayland / X11，モニター配置・倍率，他の整列・Overview 拡張の有無を記録する．
4. `journalctl --user -b -f -o cat /usr/bin/gnome-shell` でログを監視する．

## 登録とタブ操作

| 操作 | 期待する結果 |
| --- | --- |
| 右上のアイコンから左右を選択 | 同じウィンドウを重複選択できず，メインメニューは開いたまま．入力したタブ名も維持． |
| 同じアプリ・同じタイトルの2つのウィンドウを選択 | 一時的な番号で区別でき，独立した2つのウィンドウとして登録． |
| ウィンドウがない・1つだけの状態でメニューを開く | メニューは開くが，2つのウィンドウを選ぶまで登録不可． |
| メニュー表示中にウィンドウを起動・終了・タイトル変更し，閉じて開き直す | 開き直すと一覧を自動更新．終了した選択ウィンドウは解除． |
| ウィンドウのプレビューを別のウィンドウへドロップ | 対象を青枠で強調し，ドロップ終了直後に名前入力．ドロップ先が左側のウィンドウ． |
| 名前入力中に「左右を入れ替え」を押す | 左右の表示が更新され，入力したタブ名は維持．この時点では配置・登録しない．2回押すと元の順序に戻る． |
| 入れ替え後に「登録」または Enter で確定 | 表示された左右順で配置・登録し，次回のタブ表示でも順序を保持．キャンセルでは登録しない． |
| 空欄で登録，またはキャンセル / Esc | 空欄は確定せず，キャンセルでは登録・配置・最小化しない． |
| 入力中に対象ウィンドウを閉じる，またはワークスペース変更 | 入力画面が閉じ，ポインターの操作制限やエラーが残らない． |
| 対象外のウィンドウ・登録済みのウィンドウへドロップ | タブを作らない．自分自身も登録対象外． |
| 2つのタブを作り，左クリックで交互に表示 | 選択ペアを復元・左右50:50へ配置し，前ペアだけ最小化．未登録ウィンドウは変更しない． |
| 最小化・最大化・GNOME 標準タイル状態から登録 | 通常サイズへ戻して配置．内部配置を理由に登録が解除されない． |
| 6タブ以上を作成 | トップバーは先頭5タブと残り件数を表示．全タブをメニューから操作可能． |
| タブの表示・名前変更・解除 | 表示と名前が更新され，解除してもアプリは終了しない． |

## 右クリック・リサイズ・解除

| 操作 | 期待する結果 |
| --- | --- |
| 非選択タブを右クリック | メニューだけが開き，ウィンドウの表示を切り替えない． |
| 「左右を入れ替え」を選択し，別タブ経由で戻る | 対象ペアを表示・交換し，その順序を保持．2回交換で元に戻る． |
| Menu キー / Shift+F10，Esc，メニュー外クリック | 右クリックメニューを開閉できる． |
| 左または右側のウィンドウの端をドラッグしてリサイズ | そのタブを解除し，変更後のサイズを維持．他のタブは残る． |
| 登録・切り替え直後にポインター / キーボードでリサイズ | 内部配置の待機区間でも手動操作を優先し，タブを解除． |
| 最大化・最大化解除・全画面化 | タブを解除．位置だけの移動では維持． |
| 非選択タブのウィンドウを Dock から出してリサイズ・終了 | タブを解除し，拡張機能が隠した相手のウィンドウを復元． |

## アクティビティ画面と一括移動

| 操作 | 期待する結果 |
| --- | --- |
| タブ登録後に一覧を開く | 2つのウィンドウを1枚のプレビューにし，タブ名を表示．未登録ウィンドウは個別表示． |
| 合成プレビューをクリック / Enter | Overview を閉じ，両方のウィンドウを復元して分割表示． |
| 名前変更・解除・片方のウィンドウの終了後に一覧を開く | 名前や枚数が正しく，不要なプレビューや閉じるボタンが残らない． |
| 合成プレビューをドラッグ | 2つのウィンドウをまとめた表示を維持．Esc キャンセルで分離しない． |
| 別ワークスペースの背景・サムネイルにドロップ | 両方のウィンドウが同じ移動先へ移り，タブ名・登録を維持．クリックすると分割表示． |
| 動的ワークスペースの追加位置にドロップ | 新しいワークスペースに両方のウィンドウが入る． |
| 別モニターのワークスペースへドロップ | 両方のウィンドウが同モニターへ移動し，作業領域内へ配置． |
| 移動直後に片方のウィンドウをリサイズ | 通常どおりタブを解除．個別ウィンドウの通常ワークスペース移動でも解除． |
| ダイアログを開く，または片方のウィンドウを別モニターへ移す | 合成表示の条件を満たさない場合は個別表示．ダイアログは操作可能． |

## 共存と後始末

| 操作 | 期待する結果 |
| --- | --- |
| Overview 開閉と有効化・無効化を各10回程度繰り返す | タブ・メニュー・プレビューが増殖せず，シグナルやスタッキングのエラーがない． |
| 名前入力・右クリックメニュー・Overview の表示中に無効化 | UI とフックを破棄し，元の個別プレビューへ復帰．入力の操作制限が残らない． |
| 配置直後にウィンドウを閉じる・ワークスペース変更・無効化 | 古いウィンドウへの遅延操作や，無効化後の通知・再配置がない． |
| 手動最小化したウィンドウを含めて無効化 | 拡張機能自身が隠したウィンドウだけを復元．位置を勝手に戻さない． |
| 複数タブを作成し，画面ロック・解除，サスペンド・復帰を各3回 | タブ名・左右順・選択タブを保持し，非選択タブが勝手に表示されない．復帰後の左右交換・リサイズ解除も動作する． |
| ロック中にアプリが終了した場合 | 復帰時に該当タブだけ破棄し，拡張機能が隠した相手を復元する． |
| 3本指スワイプ，Dock，トップバー，Alt+Tab，画面ロック | 標準操作を継続でき，ロック画面で UI を表示しない． |
| 負座標のモニター，混在倍率，モニターの接続・切断 | 倍率の二重適用や画面外への誤配置がなく，変更後に再選択可能． |
| 最小サイズの大きいアプリ，他の整列拡張と比較 | 制約による寸法差はログに記録し，通知やリサイズのループがない．競合条件を記録． |

更新後は必ず再ログインし，古いモジュールのキャッシュを除いて確認する．結果には実施日・環境・操作・期待値・実際の結果・関連ログを記録する．
